## B. Conceptual understanding

1. **Why does the instructor insist "visual comes first, functionality comes second"?**
   Because the visual defines what the software is; only then do you translate it into numbers — a size variable (1.5) and an increase-size function [00:07:46–00:08:13]. The thinking "comes from the visual" [00:07:51–00:07:54].
2. **Why must a Unity script extend MonoBehaviour?**
   "Unity will only execute any function extending from this MonoBehaviour attached to the particular game object" — it carries everything Unity needs to attach and run the behavior [00:44:58–00:45:13]. Without it, the class is just a file with no game effect [01:02:48].
3. **Why can't a `private` member be used from another class, and what's the access pattern?**
   Same rule as C++: "I can only access from this class" [00:50:10–00:50:27]; the pattern is a public getter — "Let's say I have a private property, age… in public, I can create GetAge. And I can return it" [00:54:54–00:55:22].
4. **What does it mean that "a component is an object of its class"?**
   The class (e.g. Transform) holds the definitions; "if I add that particular on this [GameObject], that will become object of this particular class" [00:58:56–00:59:14] — "Whatever you add on any game object, that becomes a reference of that particular class" [00:59:29]. To talk to it from code, store that reference in a field [00:57:43].
5. **Why can the same script produce different results on two GameObjects?**
   "Class is a blueprint… the actual objects are these" [01:05:30–01:05:40] — each instance carries different field values ("different behaviors, different values, but same blueprint" [01:07:23]); "they're behaving differently because of the variables" [01:20:50].

## E. Compare & contrast

1. **C++ access sections vs C# per-member keywords.**
   C++: `public: … int age;` blocks [00:46:51–00:47:06]. C#: "we don't have sections… we put public or private behind that" — `public name`, `public age`, `private sleep` [00:47:07–00:47:41]; "That is the first major difference between C++ and C#" [00:47:43].
2. **C++ `vector` vs Unity `Vector3`.**
   "There is a special data type called vector, not C++ vector. That is completely different" — Unity's Vector3 holds X, Y, Z and is required for scale/position/rotation [01:40:17–01:40:53]. [AI SUPPLEMENT: C++ `std::vector` is a resizable array container.]
3. **Class vs object in this lesson's terms.**
   Class = blueprint (all definitions) [01:05:30]; object = the instance added to a GameObject, which "becomes a reference of that particular class" [00:59:29]; Unity even creates the reference for you when you drag-drop a script [01:05:47].
4. **Game view vs the rest of the editor.**
   "This game section is where what user will see… The user will not see all these things" [00:18:30–00:18:42] — Project/Hierarchy/Inspector are developer-only tooling.
5. **Transform vs SpriteRenderer.**
   Transform owns space data (position/rotation/scale — "go and ask the transform" [00:27:38]); SpriteRenderer owns what is drawn (sprite, color overlay [01:26:28]).

## F. Interview-style

1. **"How would you make one script control several objects differently in Unity?"**
   Model answer from class: declare `public` component fields, wire each object's component by drag-drop, set different field values per instance — "same blueprint, different behaviors" [01:05:30, 01:20:47]; at scale, arrays are the better structure ("The best way to do is using arrays" [01:49:36]).
2. **"Walk me through what happens when the user presses Play."**
   Unity renders from the Main Camera, applies lights ("it will go to global light"), reaches each GameObject's behaviors, and calls `Start()` first [01:37:50–01:38:15]. Unwired references then throw [01:11:58].
3. **"You know C++; what changes when writing Unity C#?"**
   Five taught differences: per-member access keywords, no class semicolon, inheritance without `public`, object creation inside MonoBehaviour, getters for privates [00:46:02–00:55:47] — plus "the logics… is same. The syntax is different" [00:55:35].
