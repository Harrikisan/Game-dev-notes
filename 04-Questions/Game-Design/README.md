# 04-Questions/Game-Design

> Question banks for **GAME_DESIGN** lessons — the concepts/design track
> (game history, genres, mechanics/rules/systems as design, player experience, balancing,
> level/progression design, idea generation, design thinking, prototyping, game analysis).

## Scope

- Lessons whose `metadata.yaml` says `primary_track: GAME_DESIGN` (canonical list:
  `00-Dashboard/GAME-DESIGN-INDEX.md`).
- Technical lessons with a substantive GAME_DESIGN secondary track may also contribute;
  label which lesson and which design aspect each question targets.

## Question emphasis

Design questions are discussion-oriented; keep answers argumentative and sourced, not
one-liners:

- **Compare & contrast** — genres, design philosophies, influential games/designers
  (tables where helpful).
- **Conceptual explanations & why/how** — e.g., why feedback loops shape player experience,
  how design thinking stages map to a game project.
- **Applied analysis** — analyze a named game's mechanics/progression/balance using the
  frameworks the class taught (games named in class are fair game; student-picked games are
  `SUPPLEMENTARY` practice).
- **Short/long-answer exam-style practice** — with marks and model answers.

## Rules

1. Traceability to the lesson's `08-source-reference.md`; no claim without a source.
2. Never claim official-exam provenance.
3. Opinion content in class (e.g., "best genre for beginners") is recorded as the
   instructor's view, not as fact.
4. When a design question needs a technical reference (e.g., "how a health system is
   implemented" as context for balancing), link to the Game-Development folder's material
   instead of duplicating it.
