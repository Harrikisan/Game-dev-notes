# 05-Practical-Activities/Game-Design

> Practical work from the **GAME_DESIGN** track — analysis exercises, documentation
> artifacts, idea-generation and prototyping practice.

## Structure

- **A — Instructor-assigned**: e.g., play-and-analyze homework ("play at least two or three
  games"), genre-study assignments, design-document tasks. Verbatim intent + timestamps via
  the lesson's `08-source-reference.md`.
- **B — Demonstrated in class**: artifacts the instructor built or walked through live
  (e.g., wireframes/GDD structure, genre breakdowns, prototype evaluation walkthroughs).
- **C — AI-generated practice**: extra design exercises (e.g., one-page design docs, genre
  mash-up briefs), always labeled `AI-SUPPLEMENTARY`, scoped to frameworks the class taught.

## Conventions

1. Each entry: activity name → lesson link → source label (A/B/C) → one-line goal →
   expected deliverable (e.g., written analysis, paper wireframe, design doc section) →
   verification checklist.
2. Games named by instructors in class are the default study material; other games are
   allowed as `SUPPLEMENTARY` practice and labeled as such.
3. Deliverables are design artifacts (documents/analyses), not code; anything requiring
   implementation belongs in `Combined-Projects/` or `Game-Development/`.
4. No duplication with lesson folders: link to `lessons/batchXX/Lxx-…/04-activities.md`.
