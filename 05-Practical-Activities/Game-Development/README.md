# 05-Practical-Activities/Game-Development

> Practical work from the **GAME_DEVELOPMENT** track — C# programs, Unity scenes/scripts,
> graphics-programming exercises (OpenGL/C++).

## Structure

- **A — Instructor-assigned**: only tasks the instructor explicitly assigned (e.g., "try to
  practice this game/project", named homework, practical tests). Verbatim intent + source
  timestamp via the lesson's `08-source-reference.md`.
- **B — Demonstrated in class**: the instructor's live builds (mini games, prefab setups,
  mixers, navmesh agents…). Listed for solo redo; full detail lives in the lesson's
  `03-code-examples.md` — link, don't re-copy.
- **C — AI-generated practice**: extra drills inside each lesson's taught patterns, always
  labeled `AI-SUPPLEMENTARY` and never attributed to the instructor.

## Conventions

1. Each entry: activity name → lesson link → source label (A/B/C) → one-line goal →
   verification checklist (what "done" looks like).
2. Tools/steps stay consistent with what the class actually used (Unity version-insensitive
   instructions where the transcript doesn't fix a version).
3. Routing from classification: lessons with `primary_track: GAME_DEVELOPMENT`, plus
   secondary-track contributions labeled per lesson.
4. No duplication with lesson folders: link to `lessons/batchXX/Lxx-…/04-activities.md`
   for the full table.
