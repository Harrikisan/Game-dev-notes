# 05-Practical-Activities/Combined-Projects

> Projects that genuinely span **design + implementation** — where a design deliverable and
> a technical deliverable are two halves of one effort.

## What belongs here

- Course-long projects the classes built across both tracks (e.g., the farming-game C#
  project from L13–L18, the Unity 2D projects, the shooting/maze projects — each includes
  design decisions *and* implementation).
- New combined work: take a design exercise from `../Game-Design/` and implement the
  mechanic with the taught engine patterns from `../Game-Development/`.

## Structure

- **A — Instructor-assigned**: projects the instructor assigned across lessons
  (including "continue/improve this project" assignments).
- **B — Demonstrated in class**: instructor-built projects to redo solo (with the design
  reasoning the instructor stated out loud, sourced via timestamps).
- **C — AI-generated practice**: combined design-then-build briefs labeled
  `AI-SUPPLEMENTARY`, restricted to taught patterns (engine features + design frameworks
  that actually appeared in class).

## Conventions

1. Each project entry lists both halves explicitly:
   - **Design side**: what to design (mechanic spec, level sketch, balance targets) —
     deliverable is a document/artifact.
   - **Implementation side**: what to build (engine/scenes/scripts) — deliverable is a
     working build or code, linking to the relevant lesson's `03-code-examples.md` patterns.
2. Every entry names the source lessons (both tracks) and their `08-source-reference.md`.
3. A combined project entry must not duplicate a lesson's `04-activities.md` — it links to
   the lesson halves and adds only the joint framing.
